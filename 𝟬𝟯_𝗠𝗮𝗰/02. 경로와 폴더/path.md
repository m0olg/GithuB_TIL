# 01 Git의 세 가지 영역

→ Git은 파일을 **작업 디렉터리 → 스테이징 영역 → 저장소** 순서로 거쳐 기록 !!

작업 디렉터리는 내가 실제로 파일을 만들고 고치는 폴더임 \
스테이징 영역은 "이번 커밋에 넣을 파일"을 잠깐 모아두는 대기실 같은 곳이고 저장소는 커밋으로 확정된 기록이 쌓이는 곳임

파일을 고쳤다고 바로 기록되는 것은 아니고, 기록할 파일을 고르는 `add`와 기록을 확정하는 `commit`, 이렇게 두 단계를 거침 \
여러 파일을 고쳤더라도 관련 있는 것끼리만 묶어서 커밋할 수 있도록 단계를 나눠둔 것임


> 작업 디렉터리  →  git add  →  스테이징 영역  →  git commit  →  저장소

# 02 현재 상태 확인하기

```bash
git status
```

저장소의 현재 상태를 보여주는 명령어로, Git을 쓰다 보면 가장 자주 입력하게 됨

출력에서 파일은 크게 세 부류로 나뉨

* `Untracked files` : Git이 아직 추적하지 않는 새 파일
* `Changes not staged for commit` : 추적 중인 파일이 수정되었지만 아직 `add`하지 않은 상태
* `Changes to be committed` : `add`까지 끝나서 커밋 대기 중인 상태

보통 터미널에서 `add` 전의 파일은 빨간색, `add` 후의 파일은 초록색으로 표시되므로 색만 봐도 어느 단계인지 알 수 있음 !

> 뭘 해야 할지 헷갈릴 때는 일단 `git status`부터 입력하면 됨

맥에서는 Finder로 폴더를 열었다 닫으면 `.DS_Store`라는 파일이 `Untracked`로 뜨는 경우가 있음 \
맥이 폴더 보기 설정을 저장하려고 자동으로 만드는 파일이라 저장소에 올릴 필요가 없으며 제외하는 방법은 `.gitignore`를 정리할 때 다룸

# 03 스테이징하기

```bash
git add 파일명
```

커밋에 포함할 파일을 스테이징 영역에 올리는 명령어

특정 파일 하나만 올릴 때는 파일명을 적고, 현재 폴더의 변경 사항을 한꺼번에 올릴 때는 파일명 대신 `.`을 씀. `git add .`은 편하지만 올리고 싶지 않은 파일(`.DS_Store`, 비밀번호나 API 키가 들어 있는 파일 등)까지 같이 섞일 수 있으므로, 실행하기 전에 `git status`로 한 번 확인하는 습관이 좋음

### 스테이징 취소하기

```bash
git restore --staged 파일명
```

`add`를 잘못했을 때 스테이징만 취소하는 명령어임 \
파일의 내용은 그대로 남아 있으므로 수정한 작업이 사라지지는 않음


<br>
<br>


# 04 커밋하기

```bash
git commit -m "커밋 메시지"
```

스테이징 영역에 올라간 내용을 저장소에 기록하는 명령어

커밋 메시지는 나중에 기록을 훑어볼 때 "그때 뭘 했는지"를 알 수 있어야 하므로 한 일을 짧고 구체적으로 적는 것이 조음 `로그인 화면 UI 추가`처럼 쓰면 되고 `수정`이나 `test`처럼 아무 정보가 없는 메시지는 피하는 편이 좋음

`-m` 없이 `git commit`만 입력하면 메시지를 쓰라며 `vim` 편집기가 열림 \
당황하기 쉬운데 `Esc`를 누르고 `:q!`를 입력한 뒤 `Enter`를 누르면 커밋 없이 빠져나올 수 있음

### 커밋이 안 될 때

* `nothing to commit`이라고 나오면 `add`한 파일이 없거나 바뀐 내용이 없다는 뜻임
* 사용자 이름과 이메일이 없다는 에러가 나오면 14번의 `git config` 설정을 먼저 해야 함

# 05 커밋 기록 확인하기

```bash
git log --oneline
```

지금까지의 커밋 기록을 한 줄씩 보여주는 명령어

그냥 `git log`를 입력하면 커밋 해시, 작성자, 날짜, 메시지가 모두 나와서 자세하지만 길어짐. `--oneline`을 붙이면 짧은 해시와 메시지만 나와서 흐름을 보기에 편함

기록이 길어서 화면이 멈춘 것처럼 보이면 `q`를 눌러서 빠져나오면 됨

맨 앞에 보이는 짧은 문자열이 커밋의 고유 번호(해시)이며 나중에 이전 상태로 되돌릴 때 이 번호를 사용하게 됨
