## 무시 파일 (.gitignore)

<br>


# 01 .gitignore란?

→ `.gitignore`는 **Git이 추적하지 않을 파일이나 폴더를 적어두는 설정 파일**

프로젝트를 하다 보면 코드가 아닌데도 폴더 안에 계속 생겨나는 파일들이 있음. 빌드하면 만들어지는 결과물, 라이브러리를 설치하면 생기는 폴더, 내 컴퓨터에서만 쓰는 설정 파일 같은 것들임

이런 파일까지 커밋에 올라가면 저장소가 지저분해지고 용량도 커짐. 그래서 `.gitignore`에 미리 적어두면 Git이 해당 파일들을 아예 없는 것처럼 취급해줌

`git status`를 했을 때 목록에 나타나지 않고, `git add .`를 해도 올라가지 않음






# 02 .gitignore를 사용하는 이유

가장 큰 이유는 **보안**임. API 키나 비밀번호, DB 접속 정보가 들어있는 `.env` 같은 파일이 GitHub에 올라가면 누구나 볼 수 있게 되고, 실제로 이런 실수로 키가 유출되는 사고가 꽤 자주 일어남

그 외에도 다음과 같은 이유가 있음

- 빌드 결과물이나 캐시처럼 매번 새로 만들어지는 파일을 올릴 필요가 없음
- `node_modules` 같은 의존성 폴더는 용량이 크고, 설치 명령어로 다시 받을 수 있음
- `.DS_Store`처럼 운영체제가 자동으로 만드는 파일이 섞이는 것을 막을 수 있음
- 개발 도구가 만드는 개인 설정 파일 때문에 팀원끼리 충돌이 나는 일을 줄일 수 있음

정리하면 **코드와 설정 중 팀이 같이 봐야 하는 것만 올리고, 나머지는 각자 로컬에만 두기 위해** 사용함






# 03 .gitignore 만드는 방법

프로젝트의 **최상위 폴더(루트)에 `.gitignore`라는 이름의 파일**을 만들면 됨. 파일 이름이 점(`.`)으로 시작하고 확장자가 없다는 점만 주의하면 됨

처음부터 직접 쓰기보다는 이미 잘 만들어진 템플릿을 가져다 쓰는 경우가 많음

- GitHub에서 저장소를 만들 때 `Add .gitignore` 항목에서 언어나 프레임워크에 맞는 템플릿을 고를 수 있음
- GitHub의 `github/gitignore` 저장소에 언어별 템플릿이 모여 있음
- gitignore.io 같은 사이트에서 사용하는 운영체제, 개발 도구, 언어를 입력하면 한 번에 만들어줌

템플릿을 가져온 뒤에 우리 프로젝트에 맞게 몇 줄 추가하는 식으로 쓰는 것이 가장 편함

> `.gitignore` 파일 자체는 팀원 모두가 같은 규칙을 써야 하므로 **커밋해서 저장소에 올리는 것이 원칙**임






# 04 작성 규칙

한 줄에 하나씩 무시할 대상을 적고, 몇 가지 기호를 알아두면 대부분 해결됨

- `#` : 주석. 이 줄은 규칙으로 취급하지 않음
- `이름/` : 슬래시로 끝나면 폴더를 의미함
- `*` : 아무 글자나 대신함. `*.log`라고 쓰면 확장자가 `.log`인 파일을 모두 무시함
- `!` : 예외 처리. 무시 대상에서 특정 파일만 빼고 싶을 때 앞에 붙임
- `/이름` : 슬래시로 시작하면 `.gitignore`가 있는 위치(루트) 기준으로만 적용함
- `**/` : 모든 하위 폴더에 걸쳐서 적용함

예를 들어 `build`라고만 쓰면 어느 위치에 있든 이름이 `build`인 파일과 폴더를 모두 무시하지만, `/build`라고 쓰면 루트에 있는 `build`만 무시함. 이 차이를 모르고 쓰면 의도치 않은 곳까지 무시되는 경우가 있어서 주의해야 함

#### 실제 파일은 이런 모양이 됨 ⬇️⬇️

```text
- 환경 변수
.env

- 의존성
node_modules/

- 빌드 결과물
build/
dist/

- 로그
*.log

- 운영체제 파일
.DS_Store

- 로그 폴더는 무시하되 이 파일은 남김
!logs/keep.log
```






# 05 이미 추적 중인 파일은 무시되지 않음

`.gitignore`를 처음 사용할 때 가장 많이 겪는 문제임

**이미 한 번이라도 커밋된 파일은 `.gitignore`에 추가해도 계속 추적됨.** `.gitignore`는 아직 추적하지 않는 파일에만 적용되기 때문임

이럴 때는 파일 자체는 지우지 않고, Git의 추적 목록에서만 빼주면 됨

```bash
git rm --cached 파일명
git rm -r --cached 폴더명
```

`--cached`가 핵심임. 이 옵션이 있어야 내 컴퓨터의 실제 파일은 그대로 두고 Git에서만 제외됨. 폴더는 안의 파일까지 처리해야 하므로 `-r`을 함께 붙임

그 뒤에 커밋해서 올리면, 이후부터는 해당 파일이 변경되어도 Git이 신경 쓰지 않음

```bash
git commit -m "추적 중이던 파일을 gitignore 대상으로 변경"
```

> 실수로 `--cached`를 빼먹으면 내 컴퓨터의 실제 파일까지 삭제되므로 꼭 확인하고 실행해야 함
