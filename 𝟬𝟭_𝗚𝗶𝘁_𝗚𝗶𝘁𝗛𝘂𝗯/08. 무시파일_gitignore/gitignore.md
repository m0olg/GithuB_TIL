## 무시 파일 (.gitignore)

<br>


# 01 .gitignore란?

→ `.gitignore`는 **Git이 추적하지 않을 파일이나 폴더를 적어두는 설정 파일**

프로젝트를 하다 보면 코드가 아닌데도 폴더 안에 계속 생겨나는 파일들이 있음. 빌드하면 만들어지는 결과물, 라이브러리를 설치하면 생기는 폴더, 내 컴퓨터에서만 쓰는 설정 파일 같은 것들임

이런 파일까지 커밋에 올라가면 저장소가 지저분해지고 용량도 커짐. 그래서 `.gitignore`에 미리 적어두면 Git이 해당 파일들을 아예 없는 것처럼 취급해줌

`git status`를 했을 때 목록에 나타나지 않고, `git add .`를 해도 올라가지 않음






# 02 .gitignore를 사용하는 이유

가장 큰 이유는 **보안**임. API 키나 비밀번호, DB 접속 정보가 들어있는 `.env` 같은 파일이 GitHub에 올라가면 누구나 볼 수 있게 되고, 실제로 이런 실수로 키가 유출되는 사고가 꽤 자주 일어남

그 외에도 다음과 같은 이유가 있음

- 빌드 결과물이나 캐시처럼 매번 새로 만들어지는 파일을 올릴 필요가 없음
- `node_modules` 같은 의존성 폴더는 용량이 크고, 설치 명령어로 다시 받을 수 있음
- `.DS_Store`처럼 운영체제가 자동으로 만드는 파일이 섞이는 것을 막을 수 있음
- 개발 도구가 만드는 개인 설정 파일 때문에 팀원끼리 충돌이 나는 일을 줄일 수 있음

정리하면 **코드와 설정 중 팀이 같이 봐야 하는 것만 올리고, 나머지는 각자 로컬에만 두기 위해** 사용함






# 03 .gitignore 만드는 방법

프로젝트의 **최상위 폴더(루트)에 `.gitignore`라는 이름의 파일**을 만들면 됨. 파일 이름이 점(`.`)으로 시작하고 확장자가 없다는 점만 주의하면 됨

처음부터 직접 쓰기보다는 이미 잘 만들어진 템플릿을 가져다 쓰는 경우가 많음

- GitHub에서 저장소를 만들 때 `Add .gitignore` 항목에서 언어나 프레임워크에 맞는 템플릿을 고를 수 있음
- GitHub의 `github/gitignore` 저장소에 언어별 템플릿이 모여 있음
- gitignore.io 같은 사이트에서 사용하는 운영체제, 개발 도구, 언어를 입력하면 한 번에 만들어줌

템플릿을 가져온 뒤에 우리 프로젝트에 맞게 몇 줄 추가하는 식으로 쓰는 것이 가장 편함

> `.gitignore` 파일 자체는 팀원 모두가 같은 규칙을 써야 하므로 **커밋해서 저장소에 올리는 것이 원칙**임






# 04 작성 규칙

한 줄에 하나씩 무시할 대상을 적고, 몇 가지 기호를 알아두면 대부분 해결됨

- `#` : 주석. 이 줄은 규칙으로 취급하지 않음
- `이름/` : 슬래시로 끝나면 폴더를 의미함
- `*` : 아무 글자나 대신함. `*.log`라고 쓰면 확장자가 `.log`인 파일을 모두 무시함
- `!` : 예외 처리. 무시 대상에서 특정 파일만 빼고 싶을 때 앞에 붙임
- `/이름` : 슬래시로 시작하면 `.gitignore`가 있는 위치(루트) 기준으로만 적용함
- `**/` : 모든 하위 폴더에 걸쳐서 적용함

예를 들어 `build`라고만 쓰면 어느 위치에 있든 이름이 `build`인 파일과 폴더를 모두 무시하지만, `/build`라고 쓰면 루트에 있는 `build`만 무시함. 이 차이를 모르고 쓰면 의도치 않은 곳까지 무시되는 경우가 있어서 주의해야 함

#### 실제 파일은 이런 모양이 됨 ⬇️⬇️

```text
- 환경 변수
.env

- 의존성
node_modules/

- 빌드 결과물
build/
dist/

- 로그
*.log

- 운영체제 파일
.DS_Store

- 로그 폴더는 무시하되 이 파일은 남김
!logs/keep.log
```






# 05 이미 추적 중인 파일은 무시되지 않음

`.gitignore`를 처음 사용할 때 가장 많이 겪는 문제임

**이미 한 번이라도 커밋된 파일은 `.gitignore`에 추가해도 계속 추적됨.** `.gitignore`는 아직 추적하지 않는 파일에만 적용되기 때문임

이럴 때는 파일 자체는 지우지 않고 Git의 추적 목록에서만 빼주면 됨

```bash
git rm --cached 파일명
git rm -r --cached 폴더명
```

`--cached`가 핵심임. 이 옵션이 있어야 내 컴퓨터의 실제 파일은 그대로 두고 Git에서만 제외됨. 폴더는 안의 파일까지 처리해야 하므로 `-r`을 함께 붙임

그 뒤에 커밋해서 올리면 이후부터는 해당 파일이 변경되어도 Git이 신경 쓰지 않음

```bash
git commit -m "추적 중이던 파일을 gitignore 대상으로 변경"
```

> 실수로 `--cached`를 빼먹으면 내 컴퓨터의 실제 파일까지 삭제되므로 꼭 확인하고 실행해야 함






# 06 이미 Push한 비밀 정보는 지워도 소용없음

`.env` 같은 파일을 실수로 GitHub에 올렸다면, 뒤늦게 `.gitignore`에 추가하고 파일을 지워도 **과거 커밋 기록에는 내용이 그대로 남아 있음**. 누구든 커밋 기록을 거슬러 올라가면 볼 수 있다는 뜻임

이런 경우에는 기록을 지우려고 애쓰기보다 **유출된 키나 비밀번호를 먼저 폐기하고 새로 발급받는 것**이 가장 확실한 대응임. 그 뒤에 필요하다면 기록에서도 제거하는 작업을 따로 진행함

그래서 비밀 정보가 담긴 파일은 **처음 커밋하기 전에** `.gitignore`부터 만들어두는 습관이 중요함






# 07 무시되는지 확인하기

규칙을 적었는데 제대로 동작하는지 헷갈릴 때는 다음 명령어로 확인할 수 있음

```bash
git check-ignore -v 파일명
```

어떤 파일의 몇 번째 줄 규칙 때문에 무시되고 있는지를 알려줌. 아무것도 출력되지 않는다면 무시되지 않는 파일이라는 뜻임

가장 간단한 방법은 `git status`를 했을 때 해당 파일이 목록에 나오지 않는지 보는 것임






# 08 알아두면 좋은 것들

## ① 무시된 파일을 강제로 추가하기

```bash
git add -f 파일명
```

`.gitignore`에 있는 파일이라도 정말 필요한 경우에는 `-f` 옵션으로 강제로 추가할 수 있음. 자주 쓸 일은 없지만 알아두면 좋음




## ② 빈 폴더 올리기

Git은 **파일이 없는 빈 폴더는 추적하지 않음**. 폴더 구조는 유지하고 싶은데 내용물은 무시하고 싶을 때는, 폴더 안에 `.gitkeep`이라는 빈 파일을 하나 만들어두는 방법을 많이 사용함

`.gitkeep`은 Git의 공식 기능이 아니라 관례로 쓰는 이름이고, 파일 이름은 아무거나 상관없음




## ③ 나만 쓰는 무시 규칙

팀 전체가 아니라 **나에게만 필요한 규칙**은 `.gitignore`에 넣지 않는 편이 좋음. 이럴 때는 두 가지 방법이 있음

- `.git/info/exclude` 파일에 적기 : 이 저장소에서만 적용되고 커밋되지 않음
- 전역 `.gitignore` 설정하기 : 내 컴퓨터의 모든 저장소에 적용됨

전역 설정은 운영체제 파일이나 내가 쓰는 편집기의 설정 파일처럼, 어느 프로젝트에서든 무시하고 싶은 것들을 넣어두기에 좋음

```bash
git config --global core.excludesfile ~/.gitignore_global
```

이렇게 경로를 지정한 뒤 해당 파일에 규칙을 적어두면 됨






# 09 .gitignore 사용할 때 주의할 점

### ① 프로젝트 시작할 때 가장 먼저 만들기

나중에 만들면 이미 올라간 파일을 정리하는 작업이 추가로 필요함. 저장소를 만들자마자 `.gitignore`부터 만들고 첫 커밋을 하는 것이 가장 깔끔함




### ② 무시하면 안 되는 파일까지 넣지 않기

너무 넓게 규칙을 쓰면 꼭 필요한 파일까지 무시될 수 있음. 예를 들어 `*.json`처럼 범위가 넓은 규칙은 설정 파일까지 모두 제외해버림. 규칙을 추가한 뒤에는 `git status`로 원하는 파일이 그대로 보이는지 확인하는 것이 좋음




### ③ 비밀 정보는 .gitignore에만 의존하지 않기

`.gitignore`는 실수를 막아주는 안전장치일 뿐이라, `git add -f`나 규칙 오타로 얼마든지 뚫릴 수 있음. 그래서 커밋하기 전에 `git status`나 `git diff --staged`로 올라가는 파일을 한 번 더 확인하는 습관이 필요함




### ④ 팀원과 규칙 공유하기

팀에서 새로운 도구나 폴더가 추가되면 `.gitignore`도 함께 업데이트하고 PR로 공유해야 함. 한 명만 규칙이 달라도 불필요한 파일이 계속 올라오게 됨






# 10 정리

- `.gitignore`는 Git이 추적하지 않을 파일과 폴더를 지정하는 파일임
- 프로젝트 루트에 만들고 팀 전체가 같은 규칙을 쓰도록 커밋해서 공유함
- 가장 중요한 목적은 `.env`, API 키 같은 비밀 정보가 GitHub에 올라가는 것을 막는 것임
- 빌드 결과물, 의존성 폴더, 운영체제 파일 등도 보통 무시 대상에 넣음
- 한 줄에 하나씩 적고, `#` 주석, `/` 폴더, `*` 와일드카드, `!` 예외 기호를 사용함
- 이미 커밋된 파일은 `.gitignore`에 추가해도 계속 추적되므로 `git rm --cached`로 추적을 끊어야 함
- 이미 Push한 비밀 정보는 지워도 기록에 남으므로 키를 폐기하고 새로 발급받아야됨
- `git check-ignore -v`로 어떤 규칙 때문에 무시되는지 확인할 수 있음
- 무시된 파일을 꼭 올려야 한다면 `git add -f`를 사용함
- 빈 폴더는 추적되지 않으므로 `.gitkeep` 같은 빈 파일을 넣어 유지
- 나만 쓰는 규칙은 `.git/info/exclude`나 전역 설정을 활용
- 프로젝트를 시작할 때 첫 커밋 전에 `.gitignore`부터 만드는 것이 가장 좋음 !!
