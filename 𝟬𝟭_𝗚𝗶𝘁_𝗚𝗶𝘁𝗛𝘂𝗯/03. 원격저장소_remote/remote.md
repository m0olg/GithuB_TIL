## 원격 저장소 (Remote Repository)

<br>

# 01 원격 저장소란?
→ **원격 저장소**는 내 컴퓨터가 아닌 서버에 저장된 Git 저장소임 (깃헙도 원격 저장소)

내 컴퓨터에 있는 저장소는 **로컬 저장소** GitHub에 있는 저장소는 **원격 저장소**라고 함

```
로컬 저장소 ↔ 원격 저장소
내 컴퓨터      GitHub
```

<br>
<br>

# 02 원격 저장소를 사용하는 이유

- 프로젝트를 온라인에 보관 가능
- 다른 컴퓨터에서도 작업할 수 있음
- 여러 사람과 코드를 공유하고 협업할 수 있음
- 로컬 컴퓨터에 문제가 생겨도 코드를 복구할 수 있음
- 프로젝트의 변경 이력을 확인 가능

<br>
<br>

# 03 로컬 저장소와 원격 저장소의 관계

> ### 로컬 저장소와 원격 저장소는 서로 연결해서 사용함
> 로컬 저장소에서 작업 ➡ 변경 사항을 원격 저장소에 업로드 ➡ GitHub에 코드 반영

> ### 🐔 **반대로** <mark>GitHub에 있는 변경 사항을 내 컴퓨터로 가져올 수도 있음</mark>
> GitHub의 변경 사항 ➡ 로컬 저장소로 가져오기

<br>
<br>

# 04 원격 저장소 이름

로컬 저장소와 원격 저장소를 연결할 때 원격 저장소에 이름을 붙여야 함

가장 일반적으로 사용하는 이름은 **`origin`** 임

```
origin = 연결된 원격 저장소를 가리키는 이름 !!!!!!!!!
```

긴 깃헙 주소를 매번 입력하지 않고 `origin`이라는 이름으로 대신 사용할 수 있음 (매우매우매우ㅐㅁ매우편리)

<br>
<br>

# 05 원격 저장소와 브랜치

원격 저장소에도 브랜치가 존재함

예를 들어 `origin/main`은 다음을 의미
* **origin** : 원격 저장소 이름
* **main** : 원격 저장소의 브랜치 이름

따라서 `origin/main`은 **원격 저장소의 main 브랜치** ⭐⭐⭐

<br>
<br>

# 06 원격 저장소에서 이루어지는 작업

> ### ✨ 원격 저장소와 관련된 작업은 크게 두 가지 !!

### ① 업로드

로컬 저장소에서 작업한 내용을 원격 저장소에 올리는 작업

```
로컬 저장소 → 원격 저장소
```

이 과정을 **push**라고 함

### ② 다운로드

원격 저장소에 있는 변경 사항을 로컬 저장소로 가져오는 작업

```
원격 저장소 → 로컬 저장소
```

이 과정에서는 **fetch**나 **pull**을 사용함 (보통 pull 많이 사용)

- `fetch`: 원격 저장소의 변경 사항을 확인하기 위해 가져오는 작업
- `pull`: 원격 저장소의 변경 사항을 가져와 현재 작업에 반영하는 작업

<br>
<br>

# 07 원격 저장소를 사용할 때 주의할 점

1. 로컬 저장소와 원격 저장소의 내용이 다를 수 있음
2. 여러 사람이 같은 파일을 수정하면 충돌이 발생할 가능성 있음
3. 작업하기 전에 원격 저장소의 최신 내용을 확인하는 것이 좋음
4. 원격 저장소에 올린 코드는 다른 사람이 볼 수 있으므로 비밀번호나 API 키를 올리면 안 됨

<br>
<br>

# 08 핵심 정리

- <mark>원격 저장소</mark>는 GitHub처럼 <mark>온라인에 있는 Git 저장소</mark>
- <mark>로컬 저장소</mark>와 연결해서 프로젝트를 <mark>공유하고 백업</mark>할 수 있음
- `origin`은 연결된 원격 저장소의 기본 이름
- `push`는 로컬 변경 사항을 원격 저장소에 올리는 작업
- `fetch`와 `pull`은 원격 저장소의 변경 사항을 가져오는 작업
- `origin/main`은 원격 저장소의 `main` 브랜치를 의미함
